# Migration Plan — Appwrite → Cloudflare

> Goal: move the entire app (auth, database, storage, hosting) off Appwrite and
> onto Cloudflare, so nothing pauses/sleeps and the whole stack runs on Workers.

## 1. Why

Appwrite (free/cloud) pauses a project after a period of inactivity. Moving to
Cloudflare removes that: Workers, D1, R2 and KV do not sleep, scale to zero cost,
and stay on one platform with one deploy pipeline.

## 2. Current architecture (source)

| Concern    | Appwrite piece                                   | Where in code |
| ---------- | ------------------------------------------------ | ------------- |
| Hosting    | Next.js 16 App Router, Server Actions data layer | `app/`, `lib/actions/` |
| Auth       | Appwrite Account — email OTP token + session     | `lib/actions/user.actions.ts`, `lib/appwrite/index.ts` |
| Session    | Cookie `appwrite-session` (session secret)       | `verifySecret`, `createSessionClient` |
| Database   | Appwrite Databases — `user` + `file` collections | `lib/actions/*.actions.ts` |
| Storage    | Appwrite Storage bucket, public view/download URLs | `uploadFile`, `constructFileUrl` in `lib/utils.ts` |
| Query      | Appwrite `Query` builder (or/equal/contains/order/limit) | `createQueries` in `file.actions.ts` |

Key data shapes the frontend depends on (must be preserved by a compatibility
mapping so we don't rewrite every component):

- User: `$id`, `accountId`, `fullName`, `email`, `avatar`
- File: `$id`, `$createdAt`, `$updatedAt`, `name`, `type`, `extension`, `size`,
  `url`, `owner` (populated object), `bucketFileId`, `users` (shared emails)

## 3. Target architecture (Cloudflare)

| Concern    | Cloudflare piece                                     | Binding / lib |
| ---------- | ---------------------------------------------------- | ------------- |
| Hosting    | Workers via **`@opennextjs/cloudflare`** (Next 16 SSR + Server Actions preserved) | `wrangler.jsonc`, `open-next.config.ts` |
| Auth       | **better-auth** + `emailOTP` plugin                  | `lib/auth.ts` |
| Email OTP  | **Resend** (transactional email)                     | `RESEND_API_KEY` |
| Session    | better-auth session cookie + D1 `session` table (KV secondary cache optional) | `lib/auth.ts` |
| Database   | **D1** (SQLite) via **Drizzle ORM**                  | binding `DB` |
| Storage    | **R2** bucket, private, streamed through an authed route | binding `BUCKET` |
| Next cache | **KV** namespace (OpenNext incremental cache)        | binding `NEXT_INC_CACHE_KV` |

### Decisions (confirmed)

1. **Auth** → better-auth + `emailOTP` plugin. Closest 1:1 to current OTP flow,
   runs on Workers, native D1 support. Needs `nodejs_compat` (AsyncLocalStorage).
2. **Email** → Resend. No domain yet → use shared sender `onboarding@resend.dev`
   for dev (delivers **only** to your Resend signup email). Production with real
   recipients needs a verified sender domain — cheapest path is registering one
   via **Cloudflare Registrar** (at-cost), then verifying it in Resend. See
   `docs/deployment-keys.md`.
3. **R2 serving** → private bucket, streamed through `/api/files/[key]` route that
   enforces session + share ACL. Preserves per-owner + shared-by-email access.
4. **Adapter** → `@opennextjs/cloudflare`. Verified to support all Next.js 16
   minor/patch versions. Requires `nodejs_compat` and compat date ≥ `2024-09-23`.

## 4. Data model (D1 + Drizzle)

better-auth owns its own tables (`user`, `session`, `account`, `verification`) —
generated by its Drizzle schema / CLI. We map the old user doc onto better-auth's
`user`: `fullName → user.name`, `avatar → user.image`. The old `accountId` concept
disappears — better-auth `user.id` is the single identity.

Application tables:

```sql
-- files
id          text primary key      -- uuid
name        text not null
type        text not null         -- document|image|video|audio|other
extension   text not null
size        integer not null      -- bytes
r2_key      text not null         -- object key in R2 (replaces bucketFileId)
owner_id    text not null references user(id)
created_at  integer not null      -- unix ms
updated_at  integer not null

-- file_shares  (replaces the Appwrite `users` array; correct + queryable)
file_id     text not null references files(id) on delete cascade
email       text not null
primary key (file_id, email)
```

`getFiles` query translation (Appwrite `Query` → Drizzle):

- `Query.or(eq(ownerId), contains(users, email))` → `files.owner_id = me` `OR`
  `exists (select 1 from file_shares where file_id = files.id and email = myEmail)`
- `Query.equal("type", types)` → `type IN (...)`
- `Query.contains("name", search)` → `name LIKE '%search%'`
- `Query.orderAsc/Desc(field)` → `orderBy(asc/desc(col))` (map `$createdAt`→`created_at`)
- `Query.limit(n)` → `.limit(n)`

### Compatibility mapping layer

To avoid rewriting every component, the actions layer returns objects shaped like
the old Appwrite documents (`$id`, `$createdAt`, `$updatedAt`, `owner` object,
`bucketFileId`, `users`). A small `toFileDoc()` / `toUserDoc()` mapper does this.
Optional later cleanup: refactor components to native field names.

## 5. Storage flow (R2)

- **Upload**: Server Action receives the `File`, writes to R2 via `BUCKET.put(key, ...)`,
  inserts a `files` row. `r2_key = ${ownerId}/${uuid}/${filename}`.
- **View/Download**: `constructFileUrl(key)` → `/api/files/<key>` (view) and
  `/api/files/<key>?download=1`. The route handler resolves the file row, checks
  the caller is owner or in `file_shares`, then streams `BUCKET.get(key)` with the
  right `Content-Type` / `Content-Disposition`.
- `next.config.ts` `images.remotePatterns` updated to allow the app's own origin
  instead of `*.cloud.appwrite.io`.

## 6. Hosting / deploy

- `@opennextjs/cloudflare` builds the Next app into a Worker.
- `wrangler.jsonc` declares bindings: `DB` (D1), `BUCKET` (R2), `NEXT_INC_CACHE_KV`
  (KV), `nodejs_compat`, `compatibility_date`.
- Secrets (`BETTER_AUTH_SECRET`, `RESEND_API_KEY`, `EMAIL_FROM`,
  `BETTER_AUTH_URL`) set via `wrangler secret put` / dashboard / GitHub Actions.
- **CI/CD**: GitHub Actions deploys to Workers **on push to `prod`** only.
  Default workflow: commit + push to `dev`; you merge `dev → prod` to release.

## 7. Risks & watch-outs

| Risk | Mitigation |
| ---- | ---------- |
| Next 16 "Proxy" architecture vs OpenNext | No middleware in this app; keep route-segment config out of any future proxy file. Pin `@opennextjs/cloudflare` + `next` versions; test `opennextjs-cloudflare build` early (Task 0). |
| Large uploads through Server Action | Workers request body cap ~100 MB. `MAX_FILE_SIZE` is 50 MB — within limits. Keep `bodySizeLimit`. |
| Email without a domain | Dev works only to your own Resend address via `onboarding@resend.dev`. Prod needs a verified domain. |
| `nodejs_compat` required | Both better-auth (AsyncLocalStorage) and OpenNext need it — set in `wrangler.jsonc`. |
| D1 write limits / migrations | Use `drizzle-kit` + `wrangler d1 migrations apply`. Run remote migrations in CI or manually before first prod deploy. |
| Frontend field coupling (`$id` etc.) | Compatibility mapper in actions layer (Section 4). |
